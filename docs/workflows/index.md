# Choose a workflow

Start with the task you need to complete. Reading an example, producing a bounded model and
building reusable components require different inputs and validation.

<div class="grid cards" markdown="1">

-   **Learn from a real result**

    Explore the committed San Juan bundle. Read the seven lessons and compare pairs without
    installing the toolkit or acquiring data.

    [Open the guided example](../examples.md)

-   **Reproduce the San Juan model**

    Use the bounded configuration and production runner in a compatible native environment.
    Keep acquisition/model execution separate from scientific export and presentation.

    [Model setup](../san-juan-demo.md) · [Reproduction guide](../documentation-examples.md)

-   **Build independent components**

    Acquire and prepare selected inputs, inspect registered stage dependencies, then build
    DEM, CHM, distance or all components for an explicit source role.

    [Pipeline stages](../pipelines.md) · [Configuration](../configuration.md)

-   **Reuse pair distances**

    Retain a validated pair product, then create named curves without reopening rasters or
    rerunning LOS. These profiles stay separate from integrated static composition.

    [Distance-product workflow](../distance-products.md)

</div>

## Working beyond the example

The [Salish Sea case study](../salish-sea-case-study.md) describes the larger regional workflow.
It is not proof that every provider, coverage area or parameter setting has been qualified.
Review sources, rights, coordinate/vertical support, vintages and coverage before a regional run.

The bounded instructional bundle records its assumptions and coverage gaps. Automated integrity
and browser checks do not establish field accuracy or novice usability. The
[validation evidence index](../development/evidence.md) distinguishes current guides from dated
run reports.
